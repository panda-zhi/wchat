# 水果销售微信小程序 — 需求分析与技术方案

| 项目 | 内容 |
| --- | --- |
| 版本 | v1.0（一期） |
| 日期 | 2026-11-17 |
| 形态 | 微信小程序（商家自营，单商家） |
| 当前阶段 | 需求已确认，待编码 |
| 交付前提 | 暂无微信支付资质，一期用模拟支付；物流只展示运单号 |

---

## 1. 项目背景与目标

### 1.1 背景

单商家水果店需要通过微信生态直接卖货，替代"微信群接龙 + 手工记账"的方式。商家需要一个能自己上架、下架、改库存的入口；顾客需要能浏览、下单、支付、查订单和运单号。

### 1.2 核心目标

1. **商品可控**：商家能随时上架/下架商品并修改库存，缺货商品不可下单。
2. **交易闭环**：顾客完成「浏览 → 加购 → 下单 → 支付 → 收货/自提 → 完成」全流程。
3. **两种履约**：支持快递发货与到店自提，下单时二选一。
4. **可平滑升级支付**：一期模拟支付跑通流程，拿到微信支付商户号后仅替换支付云函数，页面与订单逻辑不改。

### 1.3 成功指标（一期上线后观察）

- 下单到支付的转化率可统计（订单状态埋点齐全）。
- 无超卖：并发下单后 `goods.stock` 不小于 0。
- 商家上架/改库存的操作在顾客端 10 秒内可见。

## 2. 用户角色与核心场景

| 角色 | 进入方式 | 核心诉求 |
| --- | --- | --- |
| 顾客 | 微信直接打开小程序 | 看货、下单、支付、查订单/运单号 |
| 商家 | 同一小程序内的「商家管理」入口，`openid` 命中白名单才可见 | 上下架、改库存、处理订单、发货、自提核销 |

核心场景（按优先级）：

1. 顾客浏览今日水果 → 加入购物车 → 选择自提 → 支付 → 到店出示自提码。
2. 顾客直接购买 → 选择快递 → 支付 → 商家发货填运单号 → 顾客在订单详情查看运单号。
3. 商家发现某商品售罄 → 下架或改库存为 0 → 顾客端立即不可购买。
4. 顾客下单后未支付 → 15 分钟后订单自动关闭、库存自动回滚。

## 4. 功能模块拆解

### M1 商品浏览

**功能描述**：顾客查看在售商品列表与详情。

- 列表：只返回 `status = on_sale` 的商品，按 `sort` 升序、`createdAt` 降序，每页 10 条下拉加载。
- 分类：顶部 Tab（全部 / 时令水果 / 进口水果 / 果切拼盘 / 礼盒），分类为商品静态字段，不做动态管理。
- 卡片信息：封面图、名称、售价、单位（如 500g/份）、库存状态。
- 详情：轮播图、名称、卖点、售价、单位、库存、商品说明（含"生鲜商品签收后 24 小时内可申请售后"）。

**输入输出**

| 方向 | 内容 |
| --- | --- |
| 输入 | 分类 id、分页游标 |
| 输出 | `goods[]`（仅上架、库存字段脱敏为"有货/仅剩 N 件/已售罄"） |

**交互与异常**

- 库存为 0：封面加"已售罄"蒙层，详情页购买按钮置灰。
- 加载失败：显示"重试"，不清空已加载数据。
- 图片懒加载，占位骨架屏。

---

### M2 购物车

**功能描述**：本地购物车，存 `wx.setStorageSync('cart')`，不做云端同步。

- 结构：`[{ goodsId, title, coverUrl, price, unit, count }]`，价格仅用于展示，结算时以服务端价格为准。
- 操作：加购、修改数量（1–99）、删除、清空、单选/全选、合计金额实时计算。
- 加购上限：单个商品最多 99 件；购物车最多 50 个条目。

**交互与异常**

- 商品在购物车期间被下架或库存不足：进入购物车时静默校验（批量查商品），失效项标灰并提示"已失效"，结算时自动剔除。
- 计价展示用"分"转"元"统一格式化，保留两位小数。

---

### M3 下单与履约

**功能描述**：从购物车或商品详情直接下单。

**下单页字段**

| 区块 | 快递模式 | 自提模式 |
| --- | --- | --- |
| 收货信息 | 姓名、手机号、详细地址（省市区 + 门牌） | 门店名称、地址、营业时间、联系电话 |
| 商品清单 | 只读，含数量与小计 | 同左 |
| 备注 | 选填，≤ 100 字 | 同左 |
| 运费 | 固定规则：满 59 元免运费，否则 8 元 | 0 |
| 实付 | 商品合计 + 运费 | 商品合计 |

**交互逻辑**

1. 提交时前端只传 `goodsId + count + deliveryType + 地址/门店 + 备注`，**不传价格**，金额全部由云函数计算。
2. 云函数校验：商品是否存在且上架、库存是否足够 → 原子扣减库存 → 创建订单（状态 `pending_pay`）→ 返回 `orderId + 支付参数`。
3. 库存不足：返回具体商品名与剩余数量，前端提示并刷新购物车。
4. 自提模式：下单成功后生成 4 位数字自提码（同订单唯一，订单维度存储），在订单详情展示，商家核销时使用。
5. 未支付订单 15 分钟自动关闭（定时触发器，每分钟扫描），库存回滚、`sold` 回滚。

**输出**

- 订单号 `orderNo`：`yyyyMMdd` + 6 位随机数，唯一索引。
- 订单状态 `pending_pay`。

### M4 支付

**一期：模拟支付**

- 下单后弹出支付确认（文案明确标注"当前为测试支付，未真实扣款"）。
- 云函数 `pay` 内按环境开关分支：
  - `ENABLE_MOCK_PAY = true` 且调用者 openid 在白名单内 → 直接将订单置为 `paid`，写入 `payInfo.type = 'mock'`。
  - 否则返回"支付未开通"。
- **上线时必须关闭** `ENABLE_MOCK_PAY`，防止被白嫖。

**二期：真实微信支付（结构预留，不改页面）**

1. 云函数 `pay` 调 `cloud.cloudPay.unifiedOrder`（云开发微信支付，无需自建证书与回调服务器）。
2. 支付结果由 `payCallback` 云函数接收，做验签 + **按 `outTradeNo` 幂等**（重复回调直接返回成功，不重复改单）。
3. 回调成功：订单 `pending_pay → paid`，写 `transactionId`、`paidAt`。
4. 支付失败/取消：订单保持 `pending_pay`，可再次发起支付。
5. 前置条件：小程序完成**企业主体认证**并开通微信支付、商户号与小程序 AppID 绑定。

### M5 订单（顾客侧）

**列表**：按状态 Tab（全部 / 待付款 / 待发货 / 待收货 / 待自提 / 已完成 / 已取消），`openid + createdAt` 索引分页。

**可执行操作**

| 状态 | 顾客可操作 |
| --- | --- |
| 待付款 | 去支付、取消订单（回滚库存） |
| 待发货（快递） | 提醒发货（仅 toast，不做通知）、取消（需商家同意，一期置为 `refunding` 并提示联系商家） |
| 待收货 | 查看运单号、确认收货 |
| 待自提 | 出示自提码、查看门店信息 |
| 已完成 | 再次购买 |
| 已取消 | 删除订单（仅隐藏，不物理删除） |

**订单详情**：状态时间轴（下单 → 支付 → 发货/待自提 → 完成）、商品清单、收货信息、金额明细、运单号（快递）、自提码（自提）、订单号与复制。

### M6 商家端

**入口**：`我的` 页面底部显示"商家管理"，仅 `admins` 集合中存在该 openid 时渲染；云函数二次校验（前端隐藏不作为安全边界）。

#### M6.1 商品管理

| 功能 | 说明 |
| --- | --- |
| 商品列表 | 全部商品，显示状态、库存、销量，支持按状态筛选 |
| 新增 / 编辑 | 名称、卖点、分类、单位、售价（元 → 存分）、划线价（选填）、库存、排序、封面与轮播图（最多 5 张）、商品说明 |
| 上架 / 下架 | 单个切换 + 批量；下架后立即从顾客端列表与详情不可购买 |
| 改库存 | 列表内直接 ±1 / 直接输入；库存为 0 不自动下架，但顾客端显示"已售罄" |
| 删除 | 仅允许删除从未产生订单的商品；否则只能下架 |

**校验**：售价 > 0、库存为 ≥ 0 的整数、名称 ≤ 30 字、单位必填、封面必填。

#### M6.2 订单管理

| 功能 | 说明 |
| --- | --- |
| 订单列表 | 按状态 Tab：待发货、待自提、待收货、已完成、全部；显示下单时间、商品摘要、金额 |
| 发货 | 快递订单填快递公司（枚举：顺丰/京东/中通/圆通/韵达/EMS/其他）+ 运单号，状态 `paid → shipped` |
| 自提核销 | 输入或扫码顾客自提码，校验订单属于该门店且状态为 `paid` → `completed` |
| 订单详情 | 完整信息，可复制收货信息 |

**关键规则**

- 发货仅允许 `deliveryType = express` 且状态 `paid`。
- 核销仅允许 `deliveryType = pickup` 且状态 `paid`，自提码错误 3 次锁定 5 分钟（防爆破）。
- 商家不能修改订单金额。

## 5. 业务规则与状态机

### 5.1 订单状态机

```
pending_pay ──支付成功──> paid ──发货(快递)──> shipped ──确认收货──> completed
     │                     │
     │                     └──自提核销──> completed
     │
     └──超时15分钟 / 用户取消──> cancelled（回滚库存与销量）

paid ──顾客申请取消──> refunding ──商家线下退款+标记──> refunded
```

### 5.2 库存规则（核心）

1. **下单即扣库存**，不采用"支付后扣减"，避免超卖。
2. 扣减使用数据库原子操作：`where({_id, status:'on_sale', stock: _.gte(count)}).update({ stock: _.inc(-count), sold: _.inc(count) })`，判断 `stats.updated === 1` 才算成功。
3. 多商品订单逐个扣减，任一失败则**逆序回滚**已扣成功的商品，并返回失败商品信息。
4. 取消订单、超时关闭时回滚 `stock` 与 `sold`，回滚需保证幂等（订单状态流转只有一次成功）。
5. 商家手动改库存为绝对值覆盖，不参与订单回滚计算 —— 因此回滚仅在 `stock` 未被人工干预的情况下保证准确，运营上要求先处理异常订单再手工盘库。

### 5.3 金额规则

- 所有金额以**分（整数）**存储与计算，展示时除以 100。
- 运费：实付商品金额 ≥ 5900 分免运费，否则 800 分；自提订单运费恒为 0。
- 支付金额 = 商品金额 + 运费，服务端计算，客户端不参与。

### 5.4 幂等与并发

- 创建订单：前端提交按钮防重复点击（提交后禁用 3 秒），服务端不额外做幂等键（一期可接受），但支付回调必须按 `outTradeNo` 幂等。
- 同一订单的状态变更使用"带前置状态的更新"：`where({_id, status: 'paid'}).update(...)`，`updated === 0` 即视为已被处理。

## 6. 数据模型（云数据库集合）

### goods（商品）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | 自动 |
| `title` | string | 商品名 |
| `subtitle` | string | 卖点 |

| `unit` | string | 如 `500g`、`1份`、`1箱` |

| `originalPrice` | int | 划线价（分），可空 |
| `stock` | int | 可售库存 |
| `sold` | int | 累计销量 |
| `coverUrl` | string | 封面（云存储 fileID 或 https 链接） |
| `images` | string[] | 轮播图，≤ 5 |
| `description` | string | 商品说明 |
| `status` | string | `on_sale` / `off_sale` |
| `sort` | int | 排序，越小越前 |
| `specs` | array | **预留**，一期为空数组，未来存 `{ specId, name, price, stock }` |
| `createdAt` / `updatedAt` | date | |

### orders（订单）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` / `orderNo` | string | `orderNo` 唯一索引 |
| `openid` | string | 买家 |
| `items` | array | `{ goodsId, title, coverUrl, unit, price, count, subtotal }`（下单时快照） |
| `goodsAmount` / `freightAmount` / `payAmount` | int | 分 |
| `deliveryType` | string | `express` / `pickup` |
| `receiver` | object | 快递：`{ name, phone, region, detail }` |
| `pickup` | object | 自提：`{ storeName, storeAddress, code }` |
| `remark` | string | 备注 |
| `status` | string | 见状态机 |
| `payInfo` | object | `{ type: mock/wxpay, transactionId, paidAt }` |
| `express` | object | `{ company, companyCode, trackingNo, shippedAt }` |
| `cancelReason` / `closedAt` | string / date | |
| `hiddenByUser` | boolean | 顾客删除订单仅置 true |
| `createdAt` / `paidAt` / `completedAt` / `updatedAt` | date | |

### addresses（收货地址）

`openid`、`name`、`phone`、`region`（省市区数组）、`detail`、`isDefault`、`createdAt`。

### admins（商家白名单）

`openid`、`name`、`createdAt`。**仅云函数可读写**，客户端无权限。

### stores（门店）

`name`、`address`、`phone`、`businessHours`、`isActive`。一期固定 1 条。

### config（系统配置）

`key`、`value`：如 `freightFreeThreshold`、`freightFee`、`enableMockPay`、`orderTimeoutMinutes`。

### 索引

| 集合 | 索引 |
| --- | --- |
| `goods` | `status + sort`、`category + status` |
| `orders` | `orderNo`（唯一）、`openid + createdAt`（降序）、`status + createdAt` |
| `addresses` | `openid` |

### 数据库权限

| 集合 | 权限 |
| --- | --- |
| `goods` | 所有用户可读；写操作仅云函数 |
| `orders` / `addresses` | 仅创建者可读写（`doc.openid == auth.openid`），写操作仍收敛到云函数 |
| `admins` / `stores` / `config` | 仅云函数（客户端无读写） |

## 7. 技术方案

### 7.1 选型与理由

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端 | 微信小程序原生（WXML/WXSS/JS） | 单商家、页面数可控；不引入 Taro/uni-app 的构建复杂度 |
| 后端 | 微信云开发（CloudBase） | 无需服务器与域名备案、免运维；云函数天然拿到 `openid` |
| 数据库 | 云数据库（MongoDB 风格） | 商品/订单结构简单，原子 `inc` 满足库存并发 |
| 存储 | 云存储 | 商品图上传与 CDN 分发 |
| 支付 | 一期模拟支付 / 二期云开发微信支付 | 无商户号也能先跑通全流程；二期不改造页面 |
| 定时任务 | 云函数定时触发器 | 关闭超时未支付订单，无需自建 cron |

> 备选：自建 Node/Java 后端。仅在需要与其他系统对接、或后期做多商家平台时考虑，一期不选。

### 7.5 安全要点

1. **价格与金额只信任服务端**，客户端传价格一律忽略。
2. 商家能力全部在云函数内校验 `openid ∈ admins`，前端隐藏入口只做体验。
3. 顾客查询/修改订单必须带 `openid` 条件，禁止按 `_id` 直接查他人订单。
4. 云存储上传目录按 `goods/`、`avatar/` 分目录，写权限收敛。
5. 模拟支付开关存 `config` 集合并受环境变量双重控制，上线前关闭。
6. 手机号、地址属于个人信息：仅订单归属者与商家可见；小程序需配置《隐私保护指引》。

### 7.6 落地步骤

1. 注册小程序（**企业主体**）→ 获取 AppID → 开通云开发环境（基础版即可）。
2. 建集合与索引，按 6 节配置权限；`admins` 写入老板的 openid。
3. 部署 `common` 与 10 个云函数，配置定时触发器（`closeExpiredOrders`，`0 * * * * * *` 每分钟）。
4. 按 7.2 实现页面，先跑通「商品列表 → 下单 → 模拟支付 → 订单详情」主链路。
5. 补齐商家端商品管理与发货/核销。
6. 拿到商户号后：开通云开发微信支付 → 替换 `pay` 实现 → 上线 `payCallback` → 关闭模拟支付。

## 9. 验收标准

### 9.1 顾客侧

1. 首页只展示 `status = on_sale` 的商品；下架后刷新列表该商品消失，原详情页提示"商品已下架"且不可加购。
2. 库存 0 时，列表显示"已售罄"蒙层，详情页购买按钮禁用。
3. 加购、改数量、删除、全选、合计金额计算正确（含小数展示）。
4. 快递下单：`goodsAmount + freightAmount = payAmount`，满 59 元运费为 0；自提订单运费恒为 0。
5. 下单成功后库存立即减少；取消订单或超时 15 分钟关闭后库存恢复。
6. 模拟支付成功后订单变"待发货/待自提"，订单详情含支付时间。
7. 快递订单发货后，详情页可见快递公司与运单号，可一键复制。
8. 自提订单详情展示 4 位自提码与门店信息。
9. 订单列表各状态 Tab 数据正确，分页无重复无丢失。
10. 地址新增/编辑/设默认生效，默认地址在下单页自动带入。

### 9.2 商家侧

1. 非白名单 openid 看不到"商家管理"入口；直接调用 `adminGoods` 返回 403。
2. 新增商品后顾客端可搜索到；下架后立即不可购买。
3. 库存快捷修改后顾客端库存状态同步变化。
4. 只能对 `paid + express` 订单发货，重复发货被拒绝。
5. 自提核销：正确自提码 → 订单完成；错误码 → 提示剩余次数；已核销订单再次核销被拒绝。
6. 有订单的商品不可删除，提示"请改为下架"。

### 9.3 并发与异常

1. 库存 1 件时两个账号同时下单，只有 1 单成功，另一单提示"库存不足"，`stock` 不为负。
2. 多商品订单中某件库存不足时，整单失败且其他商品库存已回滚。
3. 同一支付回调重复投递 3 次，订单只变更一次状态。
4. 断网提交订单：提示网络异常，不产生脏订单（或产生后由超时任务关闭）。
